## 1. 블록 메모 실시간 공유 (개선 01)

기존 실시간 협업 인프라(STOMP 편집 토픽·`TripEvent` seq·grab 잠금)를 **재사용**해 메모 편집 경로 한 줄만 얹는 작업.
새 인프라를 짓지 않는 게 설계의 핵심이었다.

- **전용 엔드포인트 분리**: `PATCH /api/trips/{id}/blocks/{blockId}/memo` + `BlockMemoUpdateRequest`.
  이동·리사이즈(`BlockUpdateRequest`)와 섞지 않은 이유는 락 경합·이벤트 의미를 깨끗이 갈라두기 위해서다.
  메모는 `version`을 건드리지 않는다 — grab 잠금이 동시 쓰기를 이미 막으므로 낙관적 락은 중복이다.
- **저장 트리거**: per-keystroke 전송 금지. idle(≈600ms) 디바운스 + blur flush 두 시점만.
  진짜 리스크는 페이로드 크기가 아니라 **빈도**라, 디바운스로 통제했다.
- **수신측**: `BLOCK_MEMO_UPDATED`를 받되 **내가 편집 중인 블록이면 무시** — 커서 튐 방지.
- 포커스 = 해당 블록 grab(서버 게이트), blur = 해제 + flush. 타인은 그 블록을 읽기 전용으로 본다.

여기까진 순조로웠다. 문제는 이걸 **테스트로 덮으려 할 때** 시작됐다.

## 2. 테스트 도입 — 서비스 단위테스트부터

`TripServiceImpl`에 가장 사고가 잦은 로직(권한·grab·시간겹침·낙관적 락·메모)이 몰려 있어 여기부터 덮기로 했다.
매퍼·`presenceController`·`SimpMessagingTemplate`를 목으로 주입하면 DB 없이 ms 단위로 돈다.
`broadcast()`가 트랜잭션 밖에서는 `runAfterCommit`을 즉시 실행하는 성질 덕분에 브로드캐스트까지 검증된다.

기본 `./gradlew test`는 순수 단위테스트만(Docker 불필요) 돌리고, Testcontainers 기반은 `@Tag("integration")`으로
갈라 `integrationTest` 태스크로 뺐다. Docker가 없어도 회귀 안전망은 항상 green이도록.

### 삽질 1 — Mockito가 `Long` 반환에 null이 아니라 0을 준다

작성한 13개 테스트 중 절반이 엉뚱하게 "다른 사용자가 이 블록을 편집 중입니다"(409)로 터졌다.
`getGrabOwner`를 stub한 적 없는 테스트인데도 grab 게이트가 걸렸다.

한참 헤맸다. plain `mock()`으로 찍어보니 `getGrabOwner`가 **null이 아니라 `0`**을 반환하고 있었다.
`assertNotGrabbedByOther`는 `owner != null && !owner.equals(memberId)` — owner가 0이면 `0 != null`이 참,
`0 != 1`이 참 → 무조건 throw. Mockito가 `Long`(숫자 래퍼) 반환 메서드에 기본값 0을 주는 함정이었다.

→ grab 게이트를 통과해야 하는 테스트마다 `noGrab()`(= `getGrabOwner` → null 명시)을 넣었다.
전제 조건("아무도 편집 중 아님")을 드러내니 테스트도 더 읽기 좋아졌다.

### 삽질 2 — `placeBlock` 브로드캐스트 NPE

`placeBlock` 해피패스가 `Map.of("blockId", block.getId(), ...)`에서 NPE.
목킹한 `insert`가 MyBatis처럼 생성 키를 채워주지 않아 `block.getId()`가 null이었고, `Map.of`는 null 값을 거부한다.
(06-23 일지의 그 `Map.of` null 함정과 같은 결이다.)

→ `insert` stub에 `doAnswer`로 생성 id를 채워 useGeneratedKeys를 흉내 냈다. 13/13 green.

## 3. Docker 환경 구축 + Testcontainers

Docker Desktop 설치 후 WSL2를 `wsl --install --no-distribution`으로 얹었다(Docker Desktop은 자체
`docker-desktop` 배포판을 쓰므로 Ubuntu 불필요). `docker run hello-world` 통과.

### 삽질 3 — Testcontainers만 Docker와 통신 실패 (400 BadRequest)

`./gradlew integrationTest`를 돌리니 컨테이너를 못 띄웠다. `Could not find a valid Docker environment`.
로그를 파보니 진짜 원인은 **`NpipeSocketClientProviderStrategy: 400 BadRequest`** — Testcontainers가 쓰는
Java 클라이언트(docker-java)가 Docker Desktop 엔진과 named pipe로 통신하다 400을 받았다.

시도한 것들:
- `DOCKER_HOST`를 올바른 엔진 파이프(`dockerDesktopLinuxEngine`)로 지정 → 여전히 400.
- `DOCKER_API_VERSION=1.44` 고정(엔진 minAPI 1.40) → 여전히 400.
- Testcontainers 1.20.4 → 1.21.3 업그레이드 → 여전히 400.

결정적 단서: **docker CLI는 완벽히 동작**한다는 것(hello-world·compose 전부 OK).
즉 우리 코드가 아니라 **docker-java ↔ Docker Desktop 엔진 v29.6.1(API 1.55) 호환성 문제**.
엔진이 워낙 최신이라 번들된 docker-java가 negotiate를 못 한다.

→ 여기서 판단: 통합테스트를 붙잡고 씨름하는 대신, 실제 회귀 안전망인 **단위테스트에 집중**하기로.
Testcontainers는 "Docker 설정 필요"로 정리하고, 우회법(Docker Desktop의 TCP 노출 →
`DOCKER_HOST=tcp://localhost:2375`)을 `docs/setup.md §3-4`와 `AbstractIntegrationTest` 주석에 남겼다.
비용 대비 효용이 맞지 않는 지점에서 멈추는 것도 결정이다.

### 삽질 4 — 로컬 스택이 백엔드에서 crash-loop (JWT base64)

`docker compose -f deploy/local/...`로 스택을 띄우니 mysql·web은 healthy인데 backend가 재시작을 반복.
로그: `io.jsonwebtoken.io.DecodingException: Illegal base64 character: '-'`.

`JwtTokenProvider`가 `Keys.hmacShaKeyFor(Decoders.BASE64.decode(secret))`로 서명키를 만든다 —
즉 `JWT_SECRET`은 **base64여야** 한다. 그런데 예시 시크릿(`local-dev-secret-please-...`)에 `-`가 들어 있어
base64 파싱에서 터졌다. 예시 파일이 애초에 잘못돼 있었던 것.
(같은 잠재 버그가 내 `application-test.yml` 더미 시크릿에도 있었다 — Testcontainers가 뜨는 날 똑같이 터졌을 것.)

→ `openssl rand -base64 48`로 유효 base64를 만들어 로컬 시크릿·테스트 프로파일·예시 파일 2종을 모두 교정하고,
"base64여야 함" 주석을 달았다. 재기동하니 backend가 5초 만에 떴다.

### 검증

`http://localhost:8095` SPA 200, `/api/attractions` → `{"success":true, ...}`로 시드 관광지(강남 등)까지 반환.
스키마 initdb(교정된 경로)·backend↔mysql·nginx 프록시가 전부 살아 있음을 확인. Docker 환경 구축 완료.

> 참고: deploy 자산의 스키마 경로가 옛 문서 구조(`docs/02_design/`)를 가리켜 깨져 있던 것도 이 과정에서 잡았다.

## 회고

오늘 잡은 버그 4개 중 **3개가 "예제·기본값·목킹이 조용히 틀려 있던"** 종류였다.
Mockito의 0, `Map.of`의 null, 예시 파일의 non-base64 — 셋 다 코드 로직이 아니라
**"당연히 맞겠지" 하고 넘긴 전제**가 틀린 경우였다. 테스트와 실제 기동은 이런 전제를 강제로 드러낸다.

특히 JWT base64는 **단위테스트만으로는 못 잡았을** 버그다. 서비스 단위테스트는 Spring 컨텍스트를 안 띄우니까.
로컬 스택을 실제로 기동해서야 crash-loop로 드러났다. "테스트가 있다"와 "실제로 떠 있다"는 다른 층위의 확신이고,
오늘 그 둘을 나란히 확보했다.

Testcontainers 400은 분하지만 옳은 멈춤이었다. 도구 호환성 문제에 반나절을 더 쓰느니,
회귀를 실제로 막아주는 단위테스트 13개를 green으로 세워두는 게 지금 단계에서 남는 장사다.
