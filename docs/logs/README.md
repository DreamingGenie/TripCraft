# 개발 일지 (Dev Logs)

1인 추가 개발 단계의 **날짜별 내러티브 작업 일지**. 무엇을 바꿨나(→ [`CHANGELOG.md`](../../CHANGELOG.md))가 아니라
**왜·어떻게 — 고민한 지점, 삽질, 의사결정**을 남긴다.

> 팀 캡스톤 시절의 일지(`docs/capstone-1.0/logs/`)는 **동결 아카이브**(수정 금지)다.
> 이 폴더는 그 관행을 **Living 문서로 계승**해 이어간다.

## 작성 규칙

- 파일명: `YYYY-MM-DD.md` (작업일 기준, 절대 날짜).
- **의미 있는 세션에만** 쓴다 — 비자명한 결정·디버깅·설계 트레이드오프가 있을 때.
  커밋마다 쓰면 CHANGELOG 와 중복되는 오버헤드가 된다.
- CHANGELOG 와의 역할 분담: **CHANGELOG = 무엇(정본 변경 이력)**, **로그 = 왜/어떻게(서술)**.
